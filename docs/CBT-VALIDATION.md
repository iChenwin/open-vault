# V2 CBT 验证记录

日期：2026-10-21。代码在 `feature/linux-cbt`，审阅入口为 [PR #1](https://github.com/iChenwin/open-vault/pull/1)。

## 已完成的用户态验证

- Windows 全仓 `go test ./...`、`go vet ./...`。
- Linux 用户态单测：加密基线、按声明区间读取增量、父链重建、摘要校验、密文篡改拒绝、错误密钥、取消、发布失败、HEAD 持久性确认。
- 协调器测试：父代身份与序列在旋转前检查；提交完成但尚未调用驱动时可继续；驱动操作结果不确定时拒绝自动继续；提交数据损坏时保留快照。
- 驱动协议单测使用模拟 `/proc` 和固定命令执行器，验证代际、挂载、旧索引、重启状态和异常状态。它们不是内核驱动实测。
- Linux Unix socket 代理集成、后台服务异步串行/持久化/中断、真实子进程超时与进程组取消、0660 socket 权限与既有路径保护。该项使用测试 CLI，不证明内核能力。
- Chrome 无头浏览器以测试数据检查 1280px 桌面与 390px 手机页面，确认没有 JavaScript 运行异常，修复并验证窄屏页面无横向溢出。此项是界面验证。
- [控制台与代理提交的 GitHub CI](https://github.com/iChenwin/open-vault/actions/runs/39539099489) 通过静态检查、race detector 测试、真实 restic 文件备份恢复回归和构建。

## 真实内核实验状态

尚未确认通过。已建立隔离 QEMU Ubuntu 24.04 GA 6.8 实验，数据盘均为新建的普通虚拟磁盘文件，未向虚拟机传入宿主机业务盘。

早期基于固件启动的尝试未连接到 guest SSH，串口日志为空，没有执行到块备份，不能记为 CBT 成功。已改用 Canonical 校验过的 matching kernel/initrd 直接启动，并保留串口及 SSH 诊断。

最终通过必须同时具备 ext4 与 XFS 的全量/增量 JSON、减少的源读取量、重建镜像与同时间点 oracle 的字节及 SHA-256 一致、文件系统检查、文件清单一致和 `SUCCESS` 标记。对应结果将补充至此文档，未满足前不提供生产支持承诺。
