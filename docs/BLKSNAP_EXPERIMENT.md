# 外置差异数据的 CBT 实验

此文档描述 `feature/linux-cbt` 中的开发实验，不是安装教程，也不是备份可用性声明。默认分支和已发布的控制台预览包不因此获得可用的自动备份功能。

当前 dattobd 实验在真实 Ubuntu 24.04 GA 6.8 虚拟机上出现过“文件校验通过，但增量恢复镜像有两个 4 KiB 块不一致”的失败，不能作为可靠备份发布。其源卷内 COW 设计不能直接通过移动 COW 目录改为外置存储。

新实验使用独立安装的 Veeam blksnap，固定源码提交 `a162bc2064dbb1dbadf12bd1fc628bf82338d14f`（VAL-13.1），模块/CLI 协议版本 `7.0.0.0`。差异数据放在源卷之外的文件系统，保持跟踪器附着，在每次备份结束时销毁快照。Open Vault 自己负责加密仓库和恢复。CLI 版本号检查不能代替源码与构建产物校验。

## 范围与验收

- 仅针对 Ubuntu 24.04、amd64、GA `6.8.0-*-generic` 的独立 ext4/XFS 数据卷开展实验。
- Ubuntu 20.04、aarch64、5.10 内核尚未适配或验证；网页能启动不代表能进行 CBT 备份。
- `scripts/blksnap-lab/` 只在隔离 QEMU 测试机内加载模块，且只格式化由序列号识别的全新 512 MiB 测试盘；宿主机仅编译。
- 内核原语实验检查全量、保留跟踪器后的增量、快照期间写入、零范围写入、原始镜像逐字节比较、只读文件系统检查和文件清单。
- XFS 快照可能需要日志回放。实验先比较未经修改的原始镜像，再只在一次性副本上回放日志、卸载并执行只读检查；备份镜像和对照镜像保持不变。
- 程序模拟协议测试覆盖崩溃日志、损坏快照、跟踪序列/UUID/容量变化、非法位图、序列溢出和取消；这些测试不能代替真实驱动与完整应用恢复验收。

## 实验配置协议

首次真实内核记录：[运行 39578572689](https://github.com/iChenwin/open-vault/actions/runs/39578572689)，Ubuntu 24.04、6.8.0-147-generic、x86_64。ext4 的 512 MiB 全量和增量原始镜像比较、文件系统及文件清单检查通过，增量读取源快照 917,504 字节（位图粒度 65,536 字节）。XFS 全量原始镜像比较通过，随后直接对未回放日志的镜像执行 `xfs_repair -n` 失败，未进入 XFS 增量检查。因此该次整体运行**失败**，也没有验证 Go 应用备份链路。

后续实验已改为保留原始镜像，在 XFS 一次性副本回放日志后检查，并加入 Go CLI 的加密仓库、逐代恢复和脱离源卷校验；需要以相应运行的最终结果和产物为准，不能把上述 ext4 局部结果当作完整验收通过。

现有配置继续使用原 dattobd 协议。新实验必须显式设置 `provider: "blksnap"`，不允许混用 `dbdctl`。其额外字段为：

```json
{
  "provider": "blksnap",
  "blksnap": "/usr/local/bin/blksnap",
  "difference_limit": "1G"
}
```

以上仅是额外字段说明，不能单独用作配置文件。数据卷、仓库、密钥和状态目录字段仍然必需。管理员必须提前创建私有状态子目录 `state_dir/blksnap`，以及位于另一文件系统上的私有 `volume.cow_dir`，并安装经过校验的独立驱动。尚未提供面向普通用户的一键安装流程。历史仓库的列出、校验和恢复不依赖安装原驱动。

状态日志在任何改变内核状态的操作之前持久化 pending 标记；操作结果不确定、主机重启导致跟踪连续性丢失或序列溢出时拒绝增量继续运行，需要人工检查并重新建立基线，不会自动接续可能遗漏的数据。更换 provider 也不能直接接续旧 provider 的备份链。

## 开源边界

本仓库不复制或链接外部驱动源码。实验通过独立 CLI 调用上游；构建脚本在仓库之外获取固定源码，保存提交号、许可证和产物校验值。上游内核为 GPL-2.0，工具/测试为 GPL-2.0+，库/头文件为 LGPL-3.0+；具体以该固定提交的许可证为准。Open Vault 的 MIT 许可证不替代上游许可证。
