# 销售与运营角色讨论

以下为开发前的 **AI 模拟岗位评审**，不是六位真人受访或实际商业验证。销售和运营各使用三个独立角色视角，结合产品、设计、技术评审决定首版边界。

| 岗位与专家视角 | 核心意见 | 首版决策 |
| --- | --- | --- |
| 销售：售前解决方案 | 客户需要统一入口和能证明的恢复结果，不能将文件快照宣传为整机灾备 | Linux 文件目录优先，提供完整备份恢复演练 |
| 销售：MSP 与渠道 | 多机、多租户和远端纳管对渠道有价值，但会扩大身份与隔离复杂度 | 首版单机部署；多机纳管进入路线图 |
| 销售：企业采购评估 | 许可、依赖、商标、维护范围及能力声明要清晰 | MIT 代码许可，restic 独立许可，明确与群晖无关联 |
| 运营：开源社区 | 用户需要可运行示例、贡献规范、安全反馈渠道与真实限制 | 完整 README、贡献文档、安全策略和公开路线图 |
| 运营：交付与 SRE | 恢复演练、权限、互斥、可见失败和密码保管比大盘更紧要 | 专用用户、0600 密钥、串行操作、执行记录与部署指南 |
| 运营：用户成功 | 首次成功恢复是激活事件，任务创建不是终点 | 明确初始化→备份→快照→恢复→校验闭环 |

## 分歧与共识

渠道角色倾向首版就支持远端代理与多租户；SRE 角色认为应先证明本机闭环、仓库安全和恢复行为。共识是先交付单 Linux 主机的文件备份控制器，远端主机可独立部署，后续再建设纳管协议和权限隔离。

售前希望尽可能接近集中备份产品的体验；采购角色要求避免功能等价暗示。共识是提供中文任务管理和恢复流程，同时明确不含裸机恢复、虚拟机、应用一致性及完整 ABB 功能。

用户成功希望自动清理降低运维成本；SRE 角色指出保留策略涉及不可逆删除。首版不自动删除快照，并要求用户监控磁盘容量；未来保留策略需要可预览范围、明确授权和独立测试。

## 交付验收

- 新用户能够按文档完成构建、配置和启动。
- 凭据不会出现在公开样例，默认网络监听范围受限。
- 能创建任务并完成手动备份，查看结果与快照。
- 从历史快照恢复至新目录，实际比对恢复内容。
- 文档如实列出尚未实现的能力，不承诺未经测量的 RPO / RTO。
- 开源发布包含许可证、依赖说明、贡献路径和安全反馈方式。
