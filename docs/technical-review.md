# 技术岗位：三位 AI 专家讨论记录

以下是三个 AI 专家角色的独立审视视角，不代表邀请了真实人员或获得第三方背书。

## 备份存储工程师

主张 Linux 优先，首版交付文件级备份、快照列表、定时执行和指定历史版本恢复。采用成熟的 restic 负责加密、去重、增量快照和仓库格式，Go 服务负责配置、任务、认证与界面。仓库限定本地绝对路径，也可指向管理员挂载的 NAS 目录；不把对象存储凭据、多端代理和存储协议适配混入首版。

验收重点是备份内容能够恢复，而非只显示命令成功。完整校验调用 `restic check --read-data`。文件正在写入时可能得到不同时间点的内容，数据库必须先通过应用自身机制生成一致的导出文件。首版不承诺裸机恢复、块级镜像、数据库一致性或与 Synology ABB 功能完全对等。

## 安全工程师

只调用固定 restic 操作，不经过 shell。来源必须为绝对路径，解析符号链接后属于批准目录；禁止来源与仓库、恢复区、密码文件重叠。密码从专用文件读取，Unix 下拒绝组或其他用户可访问的权限，不放入网页、API 返回值或日志。子进程错误仅暴露受控文本，避免 restic 诊断意外带出密码文件位置。

恢复只接受 8–64 位十六进制快照 ID；目标名仅允许字母、数字、下划线和连字符，且必须在批准恢复根目录下创建全新目录。恢复根目录不能与备份来源、仓库或密码位置重叠。保留失败恢复的部分目录，供管理员检查，后续恢复必须另取新名称。服务监听本机回环地址，远程访问需要管理员配置带认证的 TLS 代理。

管理员必须保护配置、凭据和目录所有权：路径检查不能替代操作系统权限。恶意本机高权限进程在检查后替换目录仍属于边界风险。restic 二进制应来自可信发行渠道并及时更新。

## 测试与灾难恢复工程师

单元测试覆盖来源越界、符号链接逃逸、恢复路径穿越、已有目标拒绝、非法快照、配置重叠、Unix 密钥权限、错误脱敏、取消和子进程输出上限。真实 restic 测试通过 `RESTIC_TEST_BINARY` 启用：建立加密仓库，备份第一版文件，修改内容后产生第二个快照，删除源文件，再从第一版快照恢复并比对完整内容，同时执行完整数据校验。

测试在没有真实 restic 时会明确跳过集成用例；不能把此时单元测试成功描述成真实恢复验证成功。上线后仍应定期执行抽样恢复演练并离线保管仓库密码。密码丢失会导致加密备份无法恢复。

## 共同决定与后续边界

首版以单服务进程、单仓库、本机来源和管理员账号为范围，仓库操作串行执行，支持超时终止。定时任务错过的执行点在服务重启后按持久化状态补跑，不提供分布式调度保证。

需要后续单独设计的能力包括：备份保留与清理、多仓库、异地副本、Linux 远端代理、快照一致性、速率与存储配额、多用户权限、告警、裸机恢复和大规模监控。首版不会自动删除历史快照，因此管理员应监控容量；离线副本和隔离凭据仍是抵御勒索软件的重要措施。
